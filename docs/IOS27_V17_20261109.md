## Reproduced device free-list behavior

The emulator (`TINY_LIFO` + freed-zero + strided scattered list of 12,000
blocks > the ~6,500-block pop budget + hash-spread live/zeroed content)
reproduces the v16 map: **0 forges, SAFE/death mix 0.41–0.50 vs the device's
0.46**, structural not probabilistic.

Signature: the page's allocated class-976 blocks form a set in which **no two
elements are exactly 1,343 blocks (1,311,372 bytes) apart**. The far-read
target block is therefore never page-owned, hence never painted; its content
(zeroed vs live) is the SAFE/death mix. Model control: switching to a pairable
structure (freed fraction 50) immediately forges (`HIT=545 LEN=327744`), so
the 0-forge is the structure, not model incapacity.

## Exact wall

The class-976 free list never hands the page two blocks 1,343 apart. The
target is always outside the page's possession: zeroed → safe miss, live →
`JS_DupAtom` death. The list exceeds the pop budget, so the drain cannot reach
fresh regions either. **No page-side lever remains**; only a different
process/launch structure or a different app/device state could move it.
