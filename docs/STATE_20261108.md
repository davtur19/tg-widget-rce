# Telegram Widget Campaign — state 2026-11-08

## Objective
The unreported parser 0day RCE in the Telegram 13.x widget engine, device-proven
on iOS and Android. Android app-level impact is on builds <= 72929; beta
72979/72989 contain the widget in an isolated process.

## The bug (0day)
QuickJS-ng v0.17.0 parser `ARG_SCOPE_END`: `function f([] = eval("("))` → `b->vardefs[arg+65534]` far OOB (+1,310,700 bytes).
Unreported; **not** the public #1827. Present in Telegram 13.x on both Android and iOS.

## Universal / fast work
- **v3**: stage A v3 (Scudo-string GC priming, NP=4000/NQ=2600, tagged-int record) + the inline endgame; host 3/3 `ABLEN` and full `HF OK` ~154–158 ms.
- **Parallel fan-out** `w_v0..v3`: 4 widget sandboxes in one open, 2 attempts each, safe misses, first forger wins; host 12/12.
- **Answer channel** (`answerWidgetQuery`, field **`data`**): max answer **1024 UTF-8 bytes, no NUL**; request data **1–64 bytes**; background pacing **5000 ms** (one free request per appearance/tap); server flood 5/5 s; answer window 15 s; storage 4 KiB/area (independent → 8 answers = 8 KiB bypasses it).
- **Fast endgames**: inline v3 ~0.5–1 s; out-of-band ~5–7 s with taps (~37–42 s background); compressed 4-answer option.
- **Two-phase multiplatform (2026-11-08)**: detector widget → packed **P3** report (31 B / 64 chars) → host map → `sendWidget` of the pre-calibrated final. Two packages exist and must not be mixed: the P2/ungated pair in `bot/` (9,176 B, 48-char report) and the P3/gated pair in `payloads/two_phase/` (9,185 B, 64-char report). The P3 server is `scripts/two_phase/bot_two_phase.py`; its self-test passes from the repo. Host matrix is green for the gated pages, but they are **host-only**. Device facts: Android beta final (9,190 raw / 4,071 zlib9, beta package path) on 72929 hit stage A on the Sony, then the endgame returned `HF ERR NA` (no anchor); app alive, no proof file. Detector 63 ms, final 74 ms, host send 145 ms. On beta **72979** the widget runs in the isolated process UID 99017 (`u:r:isolated_app:s0`); PING works; the v3 detector reports `platform=1 chain=1 hit=1 att=0 sel=599`; the c2560s/v3 final hits `ABLEN[599]=327744 ATT=1` and stops at `HF ERR NOANCHOR VNC=0 VO=-1`; no `n1`; app alive. The isolated process has no app-private data access and no network permissions, so the current stage-B write and C2 are blocked even after an anchor fix. **72979 is a mitigation of impact, not a parser fix.** The current beta **72989** keeps the same model: UID 99024, `u:r:isolated_app:s0`, PING works, detector `el=55ms`, v3 final 9,190 / 4,081 zlib9, `HF ERR NOANCHOR`, no `n1`/C2, app alive. Test messages were deleted and no poller is active. The repo final also writes the release path (`org.telegram.messenger/files/n1`), so it cannot write the proof on the beta app. iOS 15 `at_final_h400` remains host-only/device-pending. iOS 27: the 8,647 B page is device-proven once (msg 5725, `rce.txt` sha256 `704984d9…`); the gated 9,139 B twin, the safe handshake and the two-phase path are host-only. **The desktop gate is withdrawn**: real Telegram Desktop and the Sony both report `maxTouchPoints=0`, same UA/platform, and DPR 2.0/2.6, so the old gate passes both and the `MT>0` fix blocks both.
