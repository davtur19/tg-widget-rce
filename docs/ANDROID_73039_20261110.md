# Android 13.2.2 / 73039 — new-beta analysis (2026-11-10)

Status: **host/static + live parser probes**. The Sony XQ-BT52 was updated to
13.2.2 / 73039 at 17:43:50 and later restored to the campaign build 73029
(data-preserving `adb install -r -d`). This note records what 73039 changes
and why the 73029 chain does not run on it.

## 1. Build identity

| item | 73029 (campaign) | 73039 (new beta) |
|---|---|---|
| version | 13.2.x, code 73029 | 13.2.2, code 73039 |
| `lib/arm64-v8a/libtwidget.so` | `db6f1281…`, 5,475,248 B | `eeb80fc2…`, 5,465,232 B |
| `lib/arm64-v8a/libtmessages.49.so` | `13f2f5fa…`, 22,131,136 B | `fdc78f59…`, 22,152,592 B |
| WidgetJS bundle | 0.6.2, 596,965 B, `0b662f63…` | 0.6.3, 596,965 B, `bf4e65ab…` |
| `sandbox-bundle.qbc` / `validator-bundle.qbc` | `3cee7ef0…` / `a0d1070b…` | `3c8b5b29…` / `af286c51…` |
| seccomp | audit, 95 insns, 30-entry deny table | unchanged byte-for-byte |

The three JS bundles and both `.qbc` files differ **only** in the version byte
(bundles) and the 8-byte source-digest header (`.qbc`); the bytecode bodies are
identical. There is no JS-level hardening and no new/removed JS API in the
bundle itself.

## 2. The parser 0day is patched — both layers

Two NEW-only semantic strings in `libtwidget.so`; the rest of `.rodata` is
relocation-only.

1. **Parser** — `js_parse_for_in_of` (OLD `0x46b188` → NEW `0x468e84`) now
   tests `fd->func_kind & JS_FUNC_ASYNC` before accepting the `await using`
   head:

   ```
   0x4690ac  cmn  w27,#0x27        ; tok == TOK_AWAIT
   0x4690b0  b.ne 0x4690d0
   0x4690b4  ldr  x8,[s,#0xa0]     ; fd = s->cur_func
   0x4690b8  ldrb w8,[x8,#0x3e]    ; func_kind
   0x4690bc  tbnz w8,#6, 0x4691c8  ; JS_FUNC_ASYNC -> accept
   0x4690c0/0x4690c4  "await using declaration is only valid in async functions"
   ```

   The same `ldrb [fd,#0x3e]; tbnz #6` pair guards the `for await` path, the
   statement/for-init `await using` paths and `js_parse_unary`'s await guard.

2. **Interpreter** — `JS_CallInternal` routes `OP_await` (138) and the other
   suspending opcodes through a guard at NEW `0x3f4aa4`:

   ```
   0x3f4aa4  ldrh w9,[b,#0x10]   ; JSFunctionBytecode.func_kind
   0x3f4aa8  tst  w9,#0x60        ; GENERATOR|ASYNC
   0x3f4aac  b.eq 0x3f4acc        ; NORMAL -> throw
   0x3f4acc  "suspending opcode in a normal function" (uncatchable)
   ```

   OLD went silently to the return epilogue at `0x3ec1e0` without
   `close_var_refs()`; that was the bug. The exception path still runs
   `close_var_refs()` and the local free.

**Live probes (73039, clean app):** every non-async form is rejected —
`for (await using … of)` and standalone `await using` in static blocks, class
field/static-field initializers, classes nested in async functions/arrows,
top-level for/declaration; only legal async contexts parse. The fix is
comprehensive; a hypothetical parser bypass would still hit the uncatchable
interpreter guard.

## 3. Engine diff

- 7,749 OLD / 7,735 NEW FDE functions; **7,713 semantically identical** after
  relocation normalisation; 19 differ, **only the two fixes are semantic**
  (the rest are codegen/relocation: a duplicated `ldr x26` in the exception
  cleanup, a register permutation).
- All chain offsets re-pin for a future entry: `SAVE 0x3e626c`,
  `RESTORE 0x3e61dc`, free tail `0x3e6f1c`, 5-arg dispatcher
  `0x3e9d0c/0x3e9d14`, `JS_CallInternal 0x3e9a78`, GLIDE `0x17e6c4`,
  `js_realloc_rt 0x3e747c`, base anchor `0x4de9d8`, syscall GOT `0x4deff8`,
  `__android_log_print@plt 0x4bcc30`. The CALA geometry is byte-identical
  (`S = caller.local_buf − 0x390`, `A=S−0x2A8`, `P=A+0x58`, `V2=S−0xB0`,
  `S0=S−0x2A0`, `SP=S−0x290`).
- **Seccomp unchanged**: 30-entry deny table byte-identical, `TRAP|0x5eed`,
  audit 95; `:widgets` still `isolatedProcess`, UID 99xxx.

## 4. JNIs moved, not removed

The nine exports that left `libtwidget.so` now live in
`libtmessages.49.so` as `WidgetClientNative_*`:

`arbiterCreate/Destroy/Down/Move/Tick/Up/Cancel/HoldDeadline` (arbiter
core/rasteriser instruction-identical to the 73029 engine copies; every
wrapper differs by one relocated `BL`) and `filterPixels`, **rewritten**
(273→347 insns) and re-signatured
`(Bitmap,int[],float[],float[],float[],int[],float)`.

`filterPixels` app-side audit: no memory bug. The five arrays are checked
equal to `n` and indexed only by `i<n`; `w/h/stride` come only from
`AndroidBitmapInfo` (never meet the array lengths); the `16·w·h` product is a
64-bit `umull` with a `≥2^60` reject; no `Get*ArrayElements`/`Critical`
lifetime; the bitmap is an app-allocated empty ARGB layer. On API ≤30 it is
reachable from a stock page only as a DoS (blur saturation / `bad_alloc` →
SIGABRT); on the API-33 target the call does not happen.

`arbiterCreate` is lazy on the first `ACTION_DOWN`; not page-drivable.

## 5. App-side leads closed on 73039

- **Widget file/URL surface:** one `https:`-only `openLink` (`Uri.parse`,
  256 B, no userinfo, host/kind pairing on both sides), one literal
  `/proc/self/cmdline` read on the engine side, two asset opens with
  `..`/absolute rejection; zero `File`/`ContentResolver`/`decodeFile`/
  `WebView`/`FileLoader`; no file bytes return to the page.
- **Images/fonts:** decode in `:widgets` (`data:` only, ≤2 MiB URI,
  `w·h ≤ 2^22`, 32 MiB budget); fonts via `Typeface.create`.
- **Payload inflate:** `GZIPInputStream`/raw `InflaterInputStream`, no output
  cap → OOM/DoS only; no length/offset drives a native copy.
- **`rich_message` → WebView:** not bot-reachable. `InputRichBlock` has no
  embed/iframe block (server rejects unknown types), the HTML mode is a fixed
  tag whitelist, the client maps `pageBlockEmbed` only for `tg-widget:` URLs,
  and `q1`'s bridge handles `resize_frame` only; `file://` is disabled at
  targetSdk 36 and `content://` is refused from the `https://telegram.org/embed`
  origin. Beacon-only in the hypothetical.
- **Normal-API 0xB0 UAF:** causally dead. Codes 11/12 are emitted by the same
  engine thread (`twidget-host`), all proxy transacts are two-way
  (`flags=0`), and the sandbox `getImageData` is a zero-filled stub. The
  engine RCE is required to issue the oneway pair.

## 6. Verdict

73039 has **no known stock entry** from the widget page: the engine parser
0day is patched in both layers, the app-side native/parser/WebView surfaces
are closed or DoS-only, and the normal-API UAF is unreachable without engine
code execution. The campaign build remains **73029**; the Sony was restored to
it data-preserving (`adb install -r -d`, 2026-11-10 18:19:30). Any future work
on 73039 needs a brand-new engine primitive (the offset table above is ready)
or a new app-process bug.
