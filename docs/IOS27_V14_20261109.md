## Why a bigger pad/spray alone does not fix coverage

Emulator, fragmented pre-heap, 40 random layouts per cell:

- **Spray size is irrelevant** (1408/2048/2600 identical): the spray is
  allocated after `b`; with a fragmented free list it is served from existing
  holes, never from the region 1.31 MB above `b`.
- Pads below ~2304 fault (4–8/40 at pre=0); 2560 is the safest single-round
  pad (39/40 hit, 0 fault).
- **Varying pad size per round is the lever**: six identical rounds re-hand
  the same blocks; six different sizes place `b` in six places.

## Exact wall

The 20 bytes at `b + 1,311,372` are either ours (forge), a zeroed free block
(safe miss), or **live/foreign/unmapped** (parser fault). A page can only
paint blocks the allocator gives it; a live block is never given. The
foreign/live 20-byte case is not fixable in JS; only the process can move it.
v14 covers the allocator-direction/fragmentation cases; the residual is a
retry/relaunch problem.
