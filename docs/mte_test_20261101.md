**Status: the QEMU user-mode MTE result is not valid. MTE remains untested.
Research dropped by decision (MTE is effectively a GrapheneOS/opt-in
feature, not a target).**

## Why the QEMU result is invalid

The Android arm64 emulator cannot run on this x86_64 host (both 37.2.12 and
35.1.21: `Avd's CPU Architecture 'arm64' is not supported by the QEMU2
emulator on x86_64 host`), so the fallback was `qemu-aarch64` user-mode with
a custom MTE-tagged allocator.

That fallback is not trustworthy:

- a minimal `irg`/`stg` test shows the tagged pointer does **not** carry the
  requested tag (tag 0/1/5 all produce unrelated top bytes), and its
  out-of-bounds access faults with `si_code=2` (invalid address), not
  `SEGV_MTESERR`;
- a **benign** quickjs script (`var a=1; print("ok")`) also faults with
  `si_code=9` in the custom allocator, so the earlier "3/3 minimal trigger"
  and "16/16 leak widget" MTE faults cannot be attributed to the exploit's
  OOB;
- the `guardrt_mte` header/tag handling and QEMU's MTE emulation are not a
  faithful model of Android's Scudo/MTE.

The previously reported conclusion "MTE blocks the OOB bootstrap" is
**retracted**. Lemmalog facts `mte_test.conclusion` and
`finding_W12.mte` were retracted; the current status is
`finding_W12.mte = not_tested`.

## What is still true

- The Android emulator arm64 guest limitation is real on this x86_64 host.
- A real MTE test needs an arm64 device/VM with MTE (`/proc/cpuinfo`
  contains `mte`), e.g. Pixel 8 or GrapheneOS with MTE enabled, or an
  arm64 cloud VM.
- The Telegram app does not declare `android:memtagMode`; MTE is off by
  default for the app. On MTE-capable hardware the exploit still runs
  unless MTE is explicitly enabled for the package
  (`adb shell am compat enable NATIVE_MEMTAG_SYNC
  org.telegram.messenger.beta`) or forced by the OS.
- The exploit itself is **11/11** on the fixed APK target without MTE
  (universal device layer: two-direction groom, padding prime,
  runtime ELF `system`).

## If a real MTE device is ever available

1. Confirm `adb shell grep mte /proc/cpuinfo`.
2. Install the beta APK, enable MTE for the package
   (`am compat enable NATIVE_MEMTAG_SYNC ...`).
3. Patch `messages_v2.data` with the universal payload and run.
4. Record whether the widget reaches `S0→S6` or dies with
   `SEGV_MTESERR` at the OOB; that is the only valid MTE datum.
