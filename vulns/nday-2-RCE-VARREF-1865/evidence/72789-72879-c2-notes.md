Date: 2026-11-05. Device: Sony XQ-BT52, Android 13, Telegram beta 13.2.0
(72879). Payload: quickjs-ng issue #1865 (`var_ref_count` truncation),
device-proven on 72799 in `notes/qjs_postsnapshot_f1865_report.md`.

## Artifact

`poc/loader_1865_72879_ok.html`

- raw **8,094 B**, zlib-9 **3,486 B** (bot: raw <= 32,768, zlib <= 4,096)
- body is only `Ok`; no canvas, PIN, markers or debug text

## 72879 constants

## Transformation pitfall

When removing the debug `mark()` block to make the loader text-only, the
replacement must cut at the **outer** `try {` that starts the universal chain:

```python
start = js.index("  var W = document.getElementById('w');")
end   = js.index("  try {\n/* universal chain", start)
js    = js[:start] + "  function mark(s) {}\n" + js[end:]
```

Cutting at the first `"  try {"` lands inside `mark()`'s `paint()` helper and
leaves a stray `try` outside the IIFE, i.e. a SyntaxError; the widget then
does nothing. Always verify the generated payload with `new Function(js)`
before patching the DB.

The #1865 bug itself is unchanged in v0.18.0/master as of 2026-11-02; PR
#1869 ("Reject functions that capture more than 65535 variables") is open.
If #1869 is merged into the engine Telegram ships, this fallback dies too and
we need the unreported N1 path or a new bug.

## Why keep it

The primary #1827 loader (3,056 B) dies as soon as the #1827 fix is in the
shipped engine. This #1865 loader is a ready, device-tested replacement for
72879, fits the bot, and has no visible debug output. It is not unreported
(issue #1865 is public), but it is the current fallback while the subagents
hunt for an unreported N1-class RCE.
