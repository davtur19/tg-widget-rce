# c4096 probe crash: root cause, corrected AB sizes, and the 2560 fallback

Date: 2026-11-08. Host-only. Worker: `hunt_parser`. No device access.

## 1. Tombstone (device/logs/tombstone_c4096_10.txt)

`SIGSEGV` code 2 (`SEGV_ACCERR`), PC `0x174d9ac` = `add_closure_variables`,
the `ldr w13,[x13,#4]` = `vd->scope_level` load:

```
x10=0xfffe (65534)            x11=0xffff (65535)
x12=0x6e5e841dd8 (vd_base)    x13=0x6e5e981dc4 (target)
target - vd_base = 0x13FFEC = 1,310,700
fault addr 0x6e5e981dc8 = target+4
```

The faulting mapping is `---> 0x6e5e85f000-0x6e6e61dfff ---` (PROT_NONE);
the target is 1.19 MB into that reservation. Both x12/x13 carry tag `0xb4`,
so this is **not** an MTE tag-check failure; the page is simply not committed.
The tag/map of the class-4096 target is compatible (b4 == b4).

## 2. Root cause (N1 `REPORT_scudo_classmap.md`)

`ArrayBuffer(len)` data is allocated as `js_mallocz(len)` →
`mf.js_calloc(opaque, 1, 8 + len)`; Scudo classifies **8+len**, not len.
The c4096 probe used `ArrayBuffer(4096)`: request 4104 → class **4352**, a
different class/tag than `b` (class 4096). The spray therefore filled the
4352 region, not the 4096 region containing the target; the first OOB vardef
read hit the uncommitted 4096 target page.

Reliable rule: `class_of(8 + len) == class_of(8 + sizeof_b)`; verify with the
diag's `ACV BSIZE` and the classmap.
